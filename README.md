# pmos：国网电力交易平台统一采集器

一份代码服务所有省份（目前：山西、辽宁、安徽）。省份之间的差异全部写在 `provinces/<省份>/` 的配置和报表规格（JSON）里，新增省份或报表一般不需要写 Python。

## 目录

```
pmos/
├── pmos/                 共用代码
│   ├── engine.py         单省工作进程：排队、限速、采集、续期保活、故障挂起
│   ├── spec.py           报表规格（JSON）与生命周期
│   ├── paging.py         分页列表（游标持久化，逐页计入台账）
│   ├── documents.py      公告栏目：列表记录 → 每个附件一个任务、业务周期推断
│   ├── province.py       省份配置与运行实例目录
│   ├── ledger.py         SQLite 任务队列 + 请求台账（先记账后发送）
│   ├── pacing.py         统一的“响应结束后间隔”和可选小时/日上限
│   ├── faults.py         失败分类，及“停哪一层、能否继续保活”的唯一决策点
│   ├── validate.py       响应判定：认证/权限/限流/未知/文件损坏
│   ├── archive.py        原件按内容哈希归档 + manifest
│   ├── excel.py          文件容器校验：xlsx/xls、公告附件按内容识别格式（不读内容）
│   ├── platform.py       PMOS 平台共性（网关头、业务码、注销提示、后台轮询接口）
│   ├── adapt.py          规范适配流程（捕获→候选→样本→启用）
│   ├── cli.py            命令行
│   └── browser/          附加已登录浏览器、四种传输方式、页面观察
├── provinces/
│   ├── shanxi/   province.json + datasets/*.json（153 个：56 导出报表 + 20 页面查询 + 77 公告栏目）
│   ├── liaoning/ province.json + datasets/*.json（133 个：70 报表 + 63 公告栏目）+ scripts/
│   └── anhui/    province.json + datasets/*.json（149 个：25 日报 + 52 期间报表 + 72 公告栏目）
├── tools/migrate_legacy.py   从三套旧代码生成报表规格（一次性迁移）
├── deploy/               systemd 模板（浏览器服务与采集服务分离）
├── docs/                 架构、适配规范、规格格式说明
└── tests/                离线测试（不开浏览器、不访问网站）
```

运行数据不进仓库，默认在 `var/<省份>/`（可用环境变量 `PMOS_DATA` 指定）：`state/`、`ledger.sqlite3`、`original/`（原件）、`samples/`（适配样本）、`captures/`（请求捕获）、`browser.json`（本机浏览器配置）。

## 快速使用

```bash
cd pmos
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pmos provinces                 # 各省报表状态统计
.venv/bin/python -m pmos shanxi check              # 校验省份配置和全部规格
.venv/bin/python -m pmos shanxi datasets --status verified
.venv/bin/python -m pmos shanxi status             # 运行状态（不连浏览器）
```

在已人工登录的浏览器旁运行采集（浏览器需开启只监听 127.0.0.1 的调试端口，见 `deploy/`）：

```bash
.venv/bin/python -m pmos shanxi run      # 前台运行工作进程（服务入口）
.venv/bin/python -m pmos shanxi start    # 打开采集；stop / pause / resume 同理
.venv/bin/python -m pmos shanxi ack auth_expired   # 人工重新登录后解除对应的阻断
```

## 关键设计

1. **浏览器与采集进程分离。** 采集器只通过本机 CDP 附加到人工登录的浏览器，从不启动、关闭、刷新或登录浏览器，重启采集器不会丢失登录。
2. **一省一进程，互不干扰。** 每省独立的运行目录、任务台账、锁和故障状态。
3. **先记账，后发送。** 每个请求在发出前写入 SQLite 台账；进程中断留下的“未结请求”必须人工确认后才继续，绝不自动重发。
4. **统一限速。** 所有请求（采集、样本、保活、时间探测）共用“上一个响应结束后至少 N 秒”；只有采集和样本计入小时/日上限。
5. **会话保活基于真实业务请求。** 网站在最后一次业务请求约 30–40 分钟后注销会话，时间接口轮询不算活动，网站自带的续期也有缺陷。业务空闲 10 分钟后，采集器会用指定报表重新读取一次已采日期来续期。队列采完、人工暂停、本地故障挂起期间都会续期；只有登录、权限、限流、网络或未知异常时才完全停止。
6. **失败分层处理。** 同一套分类决定停什么：文件损坏只隔离该报表，其余报表继续；适配样本被拒（40302）只把该报表标为 `denied`；其他情况停整个省份，等人工处理。
7. **四种传输方式覆盖三省现有做法。**
   - `fetch`：重放页面自己发出的请求模板（山西）。
   - `component`：调用页面里报表的 Vue 组件方法（辽宁、公告列表），可带准备步骤。
   - `native`：调用页面自带的前端函数（公告附件下载，签名和换票由网站完成）。
   - `ui`：像人一样填表、点查询/导出（安徽）。
8. **公告与附件统一处理。** 三省信息披露栏目共用同一后台，一个栏目一个规格：每天翻列表（遇到已知记录即停），每个新附件一个下载任务，按文件内容校验格式，按标题/记录字段推断业务周期。

- 代码与配置已完成，64 项离线测试通过（其中一项用本机无头浏览器打开本地模拟页面，测试菜单、翻页、文章弹窗和附件下载；没有可用浏览器时自动跳过）。**尚未在真实网站上运行过。**
- 迁移来的报表中，每省只有一个报表处于 `enabled`，并作为保活报表：
  - 山西：`queryRqxtfhyc`
  - 辽宁：`system_load`
  - 安徽：`actual_load`
- 旧系统已验证过的报表标为 `verified`（山西 55、辽宁 44）或 `sampled`（安徽 65：20 个日报 + 45 个期间报表）。新运行环境在该省实测通过后，再用 `pmos <省> enable <报表>` 逐个启用。
- 公告栏目：旧系统证明过列表查询、且列表里有附件的标为 `sampled`（山西 30、辽宁 50），安徽旧系统下载过原件的栏目也标为 `sampled`（51），其余为 `candidate`。新运行环境都需要先 `sample <栏目> <日期> --scope file` 下载一个附件验证。离线回放旧系统保存的列表响应：山西 77 个栏目解析出 339 个附件，辽宁 62 个栏目解析出 631 个，与旧记录一致；安徽 432 篇旧文章中 421 篇推断出的业务周期与旧系统相同，其余 11 篇（标题不含年份、需读正文）记为发布日期。
- 山西导出报表：模板没出现时不再阻断整省，而是等待；38 个报表（含保活报表）带 `bootstrap`，会调用页面自己的导出函数一次来取得原件和模板，不需要人去点“导出”。其中 37 个有旧系统缓存的页面源码佐证；保活报表的页面源码没有缓存，是按同一应用推断的，失败时只等待、不阻断。
- 山西页面查询（旧系统 24 个 JSON 配置）已迁移 20 个，标为 `sampled`：调频容量里程价格等 7 个日报表、节点电价、断面约束（76 个断面）、市场力指标、可再生能源曲线、3 个动态表、4 个成员名录、实名认证、注册公示。成员名录每份上百页、断面约束每天约 380 次请求，启用前请考虑耗时。剩余 4 个（通道可用容量 2 个、机组曲线、滚动撮合）的筛选项要每天从网站取，等“按选项生成范围”功能完成后迁移。
- 尚未迁移：安徽特殊适配（网页曲线、分类表、门户合同、成员名录等）、辽宁成员列表/历史用电/周报，正在补齐。

## 新行为

1. 每个允许采集的业务日期先读取页面当日“断面名称”清单。等待控件稳定、核对读取结束时的日期值，并保存带日期证据的原始清单响应及 SHA。
2. 只自动派发清单中的业务组合，自动发现的新断面只加入其被列出的日期。后续新日期各自读取清单，不再把全历史选项滚动铺满新日期。
3. 原 `tasks` 中未列出的组合仍保持 `pending`，不会被删除、判空、跳过或确认为完成。已有 saved/empty/failed/unknown、旧墓碑及原件不变。
4. 新 `period_options` 表单独保存日期清单、scope keys、对应 attempt、响应 SHA、ready/review 状态。空清单、格式不可信、日期证据不符或读取失败的日期留待核，不回退盲扫。
5. 请求结果已保存而计划尚未写入时中断，恢复时复用该响应，不再发出清单请求。未明请求不重发；认证、风控和网络保护继续沿用原规则。
6. 首次清单核查也覆盖以前已处理过的日期，以发现历史目录漏掉的当天选项。已消费的业务身份仍由原墓碑/消费保护跳过。

原始待采任务数仍包含待核组合。新增状态指标 `scope_review_pending` 与 `period_option_inventory` 分开展示这些数量；可选组合处理结束但仍有待核时使用 `waiting_scope_review`，不会宣称全范围采完。

这套方式保证优先采集网页当日列出的组合。网页未列出的组合是否绝对没有数据，仍未下结论；保留待核正是为了不把这一点冒充完整覆盖证明。

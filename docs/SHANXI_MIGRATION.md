# 山西迁移：对齐生产、身份核对与切换步骤

2026-10-31。依据山西会话提供的服务器只读快照（`var/shanxi_server_snapshot_20261031/`，不进 Git，含 MANIFEST/NOTES）。**本轮网站请求为0，没有操作服务器上的采集、保活、浏览器、服务或队列。**

## 生产现状（10-31 16:24）

- 浏览器是独立服务 `shanxi-browser`，采集进程用 CDP 附加，不拥有浏览器。**切换不需要重启 Chrome，也不需要重新登录。**
- 统一顺序协调器跑两条通道（原生查询、公告附件），间隔都是响应后5秒；主采集（普通导出）响应后15秒，自10-30 00:52起被自身内存门禁暂停。单 worker、共用一个“上次响应结束”时刻、不重试。
- 协调器只处理队列里已有的任务（`existing_queues_only`），不自动新增日期；按计划的65组顺序，一组排空才进下一组；用户暂缓了9个原生范围。
- 单项非鉴权失败（HTTP 5xx、非0非40302业务码、明确的传输失败、解析/校验失败）隔离后继续；鉴权、403、429、超时/结果未知、磁盘/数据库错误停止。已登记报表的 HTTP200+40302 记为 denied 继续。
- 续期：`TencentKeeper` 在距上次业务响应满300秒时，导出 `queryMarketClearingRT`（`exportTimeVoidance`）已证明归档的那一天 2026-10-30；没有 TIME 探测。页面导出取浏览器下载的 Blob，因为 CDP 的 `response.body()` 会损坏带 charset 的二进制响应。
- 队列：原生 `requests` 完成15,271、待办13,239、denied_scope 1,872；公告附件完成613、待办605。

## 切换步骤（每步需要你单独批准）

1. 在协调器一组任务之间、无在途标记时，停止 `shanxi-crawler` 和协调器（`shanxi-sequential-…`）。**浏览器服务不动。**
2. 只读冻结：复制两个队列库、Crawlee journal、计划与续期文件，并在 MANIFEST 里逐个声明在途标记的检查结果。
3. 在服务器新实例目录运行 `plan_cutover`，确认 `ready`、范围、排除原因。
4. `apply_cutover`：回执写入范围、请求预算（首批建议5次）、代码SHA、你的批准原文、`cutover.json` 的续期设置。
5. 启动 PMOS 工作进程附加到同一浏览器，预算用完自动停；核对每个请求、原件、间隔。超过约30分钟无业务请求会掉线，所以第1步到第5步要连续完成。
6. 通过后另行批准扩大预算和持续运行；失败则 `stop_all`，保留全部新事实，重新启动原服务前先把 PMOS 期间消费的身份交还旧侧。

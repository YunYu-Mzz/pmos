## 建议的小预算验收（尚未授权）

逐省单独批准和执行，先一省成功再安排下一省。范围限首批已离线核验的一个来源及其原已核范围。每省计划上限：**3个明确未消费周期的单次原生数据请求 + 2次已验证keeper业务基准请求 = 总计最多5次受控网站请求**；三省分别5次，总上限15，不能借省份剩余额度跨省使用。

前提是原owner已有合法、当前有效的页面/模板/筛选和独立保活基准。首批模板不存在时留在零请求等待，不为满足预算点击导出/刷新/导航；如果实际来源需要SDK、字典、映射或多次query/export，则本5次计划不适用，必须先列出其逐步请求数和新预算供用户批准。不能把辅助请求挤到“未计数”类别。

具体3个周期由切换时只读导出的未消费集合选择，登记精确dataset、period、dimensions、page和identity SHA；本阶段不擅自指定日期，也不重放所选9个回放样本、旧失败或unknown。两次keeper只允许原先有明确资格的基准身份，必须在批准中单独列出；不能用任意已采文件当保活授权。

观察最多45分钟，空闲约300秒触发keeper的具体策略保持该省最新授权；辽宁/山西参考15秒、安徽20秒是历史材料中的最新值，切换前重新核对，不能据本配置统一覆盖生产。真实请求一旦多于计划、身份不符、拒绝/认证/未知、间隔违规或原件无法核验，立即停止新派发，保留原浏览器及已发事实，不自行延长或重试。

## 需要用户批准的动作

1. 为指定省份在明确边界暂停旧业务派发、与原keeper/协调器进行owner交接；说明预计停等上限45分钟及原登录可能因原生操作失效，不能承诺免验证码。
2. 在原已登录Chrome上附加新版本（不重启/关闭/刷新），只执行上面登记的未消费身份和keeper基准，授权精确总请求预算；缺前置证据则零请求退出。
3. 验收失败时按预备脚本回退调度所有权，保留新增attempt/response/unknown/denied事实；若有在途未知，旧worker也保持hold。不能将旧授权复用于新错误。
4. 小预算通过后，另行批准持续队列、长稳观察和自动调度。邮件发送及飞书写入也只复用原唯一链路，单独做签名、收信和逐格读回验收，不新建第二写入端。
